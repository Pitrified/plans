# CUDA toolkit and COLMAP on g7, for splat training

- **Goal** - `nvcc` and COLMAP on g7, so gsplat can build its CUDA kernels and a capture can be posed; plan `~/repos/abyss/plans/05_threejs_scene/00_start.md` (Q4, Q5).

## Decisions

- CUDA from Ubuntu's own archive (multiverse), `cuda-toolkit` 13.1.1 (pulls `cuda-toolkit-13-1`), not NVIDIA's apt repo: no new source, and security updates come through apt.
  torch 2.15.0 from PyPI is built against CUDA 13.2; a 13.1 `nvcc` is the same major, which torch's extension build accepts.
  Simulated with `apt-get -s` on 2026-11-10: 83 new packages, nothing removed or upgraded, the driver (`nvidia-driver-595-open` 595.99.02) untouched.
- COLMAP 3.12.6 from universe: CPU-only (no CUDA in its dependencies), so feature extraction runs on the CPU.
  Fine for a few hundred frames; a CUDA build from source only if that turns out too slow.
- gcc is 15.2.0; whether `nvcc` 13.1 accepts it is checked after install, not assumed.
- No shell rc or PATH change. If `nvcc` lands off PATH, the training environment sets `CUDA_HOME` itself.
- One script, `2026-11-10_00_cuda_colmap.sh`, so the run is one line from Termux; it tees to `~/handoff-logs/`.

## Steps

User (sudo-handoff), one line:

    bash ~/repos/plans/2026-11-10_00_cuda_colmap.sh

The script runs, each teed:

    sudo apt-get update                                   # 12a-apt-update.log
    sudo apt-get install -y cuda-toolkit colmap           # 12b-apt-cuda-colmap.log

Claude, unprivileged, after reading the logs:

1. Find `nvcc` (`command -v nvcc`, else `dpkg -L cuda-nvcc-13-1 | grep bin/nvcc`), print `nvcc --version`.
2. Compile and run a one-kernel `.cu` file in the scratchpad, which checks gcc 15 against `nvcc` and the driver together.
3. `colmap -h | head -1`.
4. `nvidia-smi` still reports driver 595.99.02.

## Rollback

    sudo apt-get remove --purge -y cuda-toolkit colmap
    sudo apt-get autoremove --purge -y
